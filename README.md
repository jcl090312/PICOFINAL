# 가스 누출 조기 경보 시스템

**Pico W + MQ-2 + LED로 센서 변화와 경보 상태를 관찰하는 교육용 시제품입니다.**

GitHub에는 소스와 개발 기록을 보관하고, Thonny로 실행 파일을 Pico에 저장합니다. 웹 대시보드는 Pico가 직접 제공합니다. GitHub에 파일을 올리는 것만으로 센서 프로그램이 실행되는 것은 아닙니다.

> 측정값은 ADC 원시값이며 가스 농도(ppm)가 아닙니다. 이 프로젝트는 인증된 가스 경보기의 대체품이 아닙니다. 실제 가스 검출 성능과 배선은 별도로 검증해야 합니다.

## 1. 준비물과 파일

### 준비물

- Raspberry Pi **Pico W / WH 또는 Pico 2 W**와 해당 보드용 MicroPython
- `VCC, GND, AO, DO`가 표시된 MQ-2 모듈 1개
- 초록·노랑·빨강 LED 각 1개, LED용 330Ω 저항 3개
- 센서 출력 분압용 10kΩ 저항 2개
- 브레드보드, 점퍼선, 데이터 통신이 되는 USB 케이블
- Thonny, 같은 로컬 네트워크에 연결할 휴대전화 또는 PC

금속 캔 형태의 MQ-2 센서 단품은 별도 히터·부하 회로가 필요합니다. 아래 배선은 4핀 모듈을 가정합니다. 일반 Pico는 Wi-Fi가 없으므로 웹 기능에는 W 계열이 필요합니다. [1][2][3]

### 파일별 역할

| 파일 | 역할 | Pico에 저장 |

| `.gitignore` | 실제 Wi-Fi 비밀번호와 임시 파일 제외 | 아니요 |

추가 pip 패키지는 없습니다. `machine`, `network`, `uasyncio` 등은 **보드용 MicroPython이 제공하는 모듈**입니다. PC의 일반 Python에 이 이름의 패키지를 설치해서 해결하는 방식이 아닙니다. [2][4]

## 2. 배선: 전원을 끈 상태에서 연결

### MQ-2 전원과 아날로그 출력

MQ-2 제조사 표준 회로는 히터 전원 5V를 사용합니다. 반면 Pico ADC 입력은 0~3.3V 범위입니다. **MQ-2 AO를 GP26에 직접 연결하지 마세요.** 제조사 시험 출력도 3.3V를 넘을 수 있으므로 아래 분압을 사용합니다. [2][3][5]

| 부품 단자 | 연결 |
|---|---|
| MQ-2 `VCC` | USB로 Pico를 구동할 때 `VBUS`, 물리 핀 40 |
| MQ-2 `GND` | Pico `GND`, 예: 물리 핀 38 |
| MQ-2 `AO` | 10kΩ 저항 R1의 한쪽 끝 |
| R1의 다른 끝 | **분압 중간점**: GP26, 물리 핀 31에 연결 |
| 분압 중간점 | 두 번째 10kΩ 저항 R2를 거쳐 GND에 연결 |
| MQ-2 `DO` | 이번 코드에서는 연결하지 않음 |

연결을 문장으로 쓰면 **AO → R1(10kΩ) → 중간점 → R2(10kΩ) → GND**이며, **GP26은 중간점에 연결**합니다. AO와 GP26 사이에 저항 하나만 넣는 것은 이 분압 회로와 다릅니다.

두 저항의 값이 같으면 계산상 중간점 전압은 AO 전압의 절반입니다. 예를 들어 AO가 5.0V이면 GP26은 약 2.5V입니다. 실제 연결 후에는 멀티미터로 GP26-GND 사이가 3.3V를 넘지 않는지 확인하세요.

VBUS는 USB 전원에 의존합니다. 센서 히터 소비전력은 제조사 기준 최대 950mW이므로 USB 공급과 모듈 사양을 확인하세요. 센서 전원을 GPIO나 3V3 핀에서 공급하지 않습니다. 이 안내는 USB 전원 구성이며 별도 5V 전원을 병렬로 연결하는 구성은 포함하지 않습니다. [1][3]

### LED

| 색 | GP 번호 | 물리 핀 | 연결 |
|---|---:|---:|---|
| 초록 | GP14 | 19 | GP14 → 330Ω → LED 긴 다리(+), 짧은 다리(-) → GND |
| 노랑 | GP15 | 20 | GP15 → 330Ω → LED 긴 다리(+), 짧은 다리(-) → GND |
| 빨강 | GP16 | 21 | GP16 → 330Ω → LED 긴 다리(+), 짧은 다리(-) → GND |

물리 핀 번호와 GP 번호는 다릅니다. 코드에는 `14, 15, 16, 26`처럼 **GP 번호**를 씁니다. 핀 배치는 Pico W 공식 자료를 기준으로 했습니다. [1]

빨간 LED만 있다면 `config.py`의 `GREEN_LED_PIN = None`, `YELLOW_LED_PIN = None`으로 바꿀 수 있습니다. 이 경우 주의·예열 표시등은 생략되고 웹 화면의 상태와 빨간 위험 경보를 확인합니다.

### 선택 사항: 부저

기본값은 `BUZZER_PIN = None`이며 부저가 없어도 실행됩니다. 실제 부저를 추가하려면 부품의 정격·전류를 먼저 확인하고 **3.3V 논리 입력을 받는 능동 부저 구동회로**를 사용하세요. 그 회로의 입력 핀에 사용할 GP 번호를 `BUZZER_PIN`에 지정합니다. 원시 부저나 5V 부하를 GPIO에 직접 연결하지 않습니다. 수동 부저용 PWM 출력은 이번 버전에 포함하지 않았습니다.

## 3. Thonny에서 실행

1. 압축을 풀고, 피코에 들어갈 파일을 PC의 한 폴더에 둡니다.
2. Pico W를 USB로 연결합니다. Thonny의 인터프리터를 **MicroPython (Raspberry Pi Pico)**로 선택하고 보드의 포트를 고릅니다. 기존 코드가 이미 실행된다면 펌웨어를 다시 설치할 필요는 없습니다.
3. `wifi_config.example.py`를 복사해 **`wifi_config.py`**로 저장합니다. Thonny용 압축에는 이 이름의 빈 설정 파일이 들어 있습니다.
4. 아래 두 줄에 자신의 **2.4GHz Wi-Fi** 이름과 비밀번호를 입력합니다. 빈 SSID는 Wi-Fi 없이 센서·LED만 실행하는 설정입니다. [2]

```python
WIFI_SSID = "내_와이파이_이름"
WIFI_PASSWORD = "내_와이파이_비밀번호"
```

5. 기존 프로그램이 실행 중이면 Thonny의 중지 버튼으로 멈춥니다. 파일 보기에서 아래 **5개 파일을 모두 Pico의 최상위 폴더**로 올립니다. 같은 이름의 기존 파일을 교체할 때는 PC에 먼저 사본을 보관하세요. 준비 파일을 먼저 올리고 `main.py`를 마지막에 올리면 좋습니다.

   `main.py`, `alarm_logic.py`, `config.py`, `dashboard.html`, `wifi_config.py`

   Python 파일은 각각 저장 대상을 `Raspberry Pi Pico`로 선택해 저장할 수도 있습니다. HTML은 파일 목록에서 PC 파일을 선택해 장치로 업로드하세요. `main.py`만 올리면 나머지 파일을 찾지 못합니다.

6. 처음에는 `config.py`의 `SIMULATION = True`로 저장하고 Pico를 재시작하여 LED와 화면 흐름을 확인합니다. 이 모드에서는 실제 센서를 읽지 않습니다.
7. 실측 준비가 되면 **`SIMULATION = False`**로 되돌려 Pico에 저장하고 다시 시작합니다.
8. Thonny Shell에 표시되는 `대시보드 주소: http://...`를 같은 네트워크의 휴대전화·PC에서 엽니다. 코드를 바꾸어 저장한 뒤에는 Pico를 재시작해야 설정이 다시 적용됩니다.

공유기에서 기기 간 통신을 차단하는 게스트 Wi-Fi나 학교·기관망은 같은 이름의 Wi-Fi에 접속해도 접속이 안 될 수 있습니다. 먼저 서로 통신 가능한 로컬 네트워크에서 확인하세요.

파일을 모두 저장하면 전원을 다시 넣었을 때 `main.py`가 실행됩니다. Thonny의 중지 버튼은 측정을 중단하므로, 시험을 마친 뒤 자동 실행을 확인할 때는 다시 실행하거나 전원을 껐다 켜세요.

## 4. 상태 판정과 표시

센서는 약 1초마다 읽습니다. 매번 5개 ADC 값을 짧게 읽고 중앙값을 사용합니다. 그래프와 판정에 쓰는 `raw`는 이 중앙값입니다.

| 상태 | 판정·의미 | 외부 LED 기본 동작 |
|---|---|---|
| 측정 준비 | 아직 첫 측정 전 | 노랑 느린 점멸 |
| 예열 중 | 시작 후 관찰 안내 중, 현재 확정 경보 없음 | 노랑 느린 점멸 |
| 정상 | 안내 시간 이후, 확정 경보·진단 이상 없음 | 초록 켜짐 |
| 주의 | 보통 ADC 18000 이상에 대한 동일 후보 3회 확인, 또는 급상승 확인 | 노랑 켜짐 |
| 위험 | ADC 30000 이상에 대한 동일 후보 3회 확인 | 빨강 빠른 점멸 |
| 센서 점검 | ADC 읽기 오류 또는 지속적인 신호 이상 | 노랑·빨강 교대 점멸 |

보드 내장 LED는 Wi-Fi 연결 여부를 나타냅니다. 연결되면 켜지고 연결 전에는 짧게 깜박입니다. 외부 빨간 LED와 용도가 다릅니다.

### 경계에서 상태가 계속 바뀌지 않도록 한 규칙

- 경보를 올릴 때는 같은 상위 상태 후보를 **3회 연속** 확인합니다.
- 현재 위험이면 **28000 미만**, 현재 주의이면 **16000 미만**에서 하향 전환 후보가 생깁니다. 경곗값 28000·16000은 기존 경보를 유지합니다.
- 같은 하위 상태 후보가 **5회 연속**이면 낮은 단계로 전환합니다. 위험에서 낮은 정상 범위로 바로 내려가면 5회 후 정상으로 갈 수 있습니다.
- 직전 측정과의 실제 시간 차이로 계산한 증가 속도가 **초당 8000 이상, 2회 연속**이면 최소 주의로 올립니다. 이때 일반 상승의 3회를 다시 기다리지 않습니다.
- 읽기 실패나 하한 부근의 신호는 정상 복귀 근거로 사용하지 않습니다. 진단 이상에서 회복 중일 때는 경보 해제도 보수적으로 늦춥니다.

이 판정은 순간 잡음으로 인한 잦은 전환을 줄이는 대신 경보 지연을 추가합니다. 1초 간격의 3회 확인을 실제 누출 후 정확히 3초 내 검출한다는 보장으로 해석하면 안 됩니다.

### 예열 안내와 실제 안정화

`WARMUP_SECONDS = 180`은 **프로그램 시작 후 관찰 안내 시간**입니다. 이 타이머가 끝났다고 센서가 교정되거나 안정화가 보장되는 것은 아닙니다. Winsen의 MQ-2 표준 시험조건에는 48시간 이상의 예열이 명시되어 있으므로, 처음 사용하는 센서는 구매한 모듈의 지침을 따라 충분히 예열·안정화하고 기준을 정해야 합니다. [3]

예열 안내 중에도 높은 값에 대한 주의·위험 경보는 동작합니다. 예열 변동과 실제 가스 반응을 코드만으로 구분할 수는 없습니다.

### 기준값을 해석하는 방법

18000·30000은 사용자 기존 코드에서 가져온 **실험용 예시값**입니다. 분압을 추가하면 같은 센서 출력에 대한 ADC 값이 바뀌므로 실제 배선 후 기준을 다시 검토해야 합니다. 분압 회로 자체도 모듈의 아날로그 출력에 부하를 줄 수 있습니다.

대시보드 전압은 `raw × 3.3 ÷ 65535`로 구한 **GP26 입력의 근사 전압**입니다. 센서 AO 원래 전압이나 ppm을 뜻하지 않습니다. `percent`를 API에서 사용한다면 ADC 전체 범위에 대한 비율일 뿐입니다. [2]

### 센서 신호 점검의 한계

ADC 읽기 예외는 즉시 점검 상태로 처리합니다. 100 이하 또는 65000 이상의 입력이 10회 연속이면 신호 이상을 표시합니다. 상한 신호에서 확정된 위험은 점검 표시 때문에 해제하지 않습니다.

이 규칙은 단선·전원 문제·입력 포화의 단서이며 모든 고장을 검출하지는 못합니다. 값이 평평하다는 이유만으로 고장이라고 판단하지 않습니다. 진단 이상이 없는 표시도 센서 정확성을 보장하지 않습니다.

## 5. 웹 대시보드와 알림

### 제공하는 기능

- 현재 값, 상태, 변화량, ADC 입력 전압
- 최근 측정 그래프, 주의·위험 기준선
- 최근 보관 구간의 평균·최댓값·최솟값
- 최근 유효 측정 수와 전체 측정 시도 수의 구분
- 예열 안내, 신호 점검, 상태 전환 대기, 가상 시험 표시
- 상태 변화·회복·신호 이상·급상승 이벤트
- 측정 기록 CSV와 이벤트 CSV 각각 다운로드
- 사용자가 버튼을 눌러 켜는 브라우저 소리
- 지원되는 보안 연결의 데스크톱 브라우저 알림

웹 요청은 제한 시간과 동시 접속 수 제한을 사용합니다. 한 요청이 끝난 뒤 다음 데이터를 요청하므로 브라우저 요청이 계속 겹치지 않습니다. 연결 실패뿐 아니라 같은 측정 ID가 계속 돌아오는 경우도 측정 갱신 중단으로 표시합니다. 오래된 정상 값을 새 정상 상태처럼 보여주지 않습니다.

### 휴대전화 푸시가 안 된 이유

기존 코드의 `http://피코IP` 접속은 일반적으로 알림에 필요한 보안 컨텍스트가 아닙니다. 또한 `new Notification()`은 많은 모바일 브라우저에서 지원 방식이 다릅니다. 이번 화면은 이 제한을 설명하고 사용할 수 없는 알림 버튼을 비활성화합니다. [6]

| 경보 방식 | 이번 버전의 범위 |
|---|---|
| Pico LED | 브라우저·Wi-Fi 없이도 로컬에서 작동 |
| 웹 화면 경고 | 대시보드가 새 데이터를 받는 동안 작동 |
| 브라우저 소리 | 사용자가 켠 뒤 페이지 실행이 유지되는 동안 작동 |
| OS 알림 | 지원·권한·보안 연결 조건을 만족한 데스크톱 환경에서 시도 |
| 화면 잠금·페이지 종료 후 원격 푸시 | 미구현 |

진짜 백그라운드 푸시는 HTTPS 페이지, Service Worker, Push 구독, 이벤트를 전달할 서버 등의 별도 구조가 필요합니다. GitHub Pages에 HTML을 올리는 것만으로 Pico의 사설 IP에 접근하거나 원격 푸시가 구성되지는 않습니다. [6][7]

브라우저 소리 끄기는 웹 소리만 끕니다. Pico의 LED와 설정된 부저 출력은 계속 동작합니다.

## 6. 기록 보관

- 최근 측정 **60개**, 이벤트 **30개**를 Pico RAM에 보관합니다.
- 처음에는 기록 수가 적으며, 읽기 실패도 빈 값의 측정 시도로 남깁니다.
- 평균·최댓값·최솟값은 최근 구간의 유효값만 계산합니다. 실제 ADC 0은 결측값과 다르게 보관합니다.
- 전체 측정 시도 수는 별도로 셉니다. 최근 60개가 전체 기간의 기록을 뜻하지 않습니다.
- CSV는 Excel에서 한국어를 읽기 쉽도록 UTF-8 BOM을 포함합니다.
- CSV 시간은 **이번 부팅 이후 경과초**이며 날짜·시각이 아닙니다. `부팅ID`와 `입력출처`를 함께 기록합니다.
- **전원을 끄거나 재시작하면 RAM 기록이 사라집니다.** 필요한 기록은 각 다운로드 버튼으로 먼저 저장하세요. CSV도 최근 보관분만 포함합니다.

이번 버전에는 매초 플래시 쓰기나 자동 장기 저장을 넣지 않았습니다. 장기 보관은 다음 단계에서 PC·서버·SD카드 등 저장 대상을 정한 뒤 추가합니다.

## 7. GitHub에 올리기

1. GitHub용 압축을 풀어 나온 파일과 폴더를 저장소에 올립니다. ZIP 파일 한 개만 올리는 것보다 압축을 푼 소스를 올려야 코드와 README를 바로 볼 수 있습니다.
2. 실제 비밀번호가 없는 `wifi_config.example.py`를 올립니다. **비밀번호가 든 `wifi_config.py`는 올리지 않습니다.**
3. `.gitignore`도 함께 올립니다. 다만 이미 Git에서 추적한 비밀번호 파일이나 웹 업로드로 직접 선택한 파일을 `.gitignore`가 자동으로 안전하게 처리해 주지는 않습니다. 업로드할 파일을 직접 확인하세요.
4. 코드 수정 후 Pico에도 같은 실행 파일을 다시 저장하여 두 사본을 맞춥니다.

## 8. PC에서 먼저 확인하기

Pico가 없어도 판정 로직과 가상 대시보드를 확인할 수 있습니다. Windows에서는 압축을 푼 GitHub 폴더의 주소창에 `cmd`를 입력해 터미널을 열고 다음을 실행합니다.

```bat
python -m unittest discover -s tests -v
```

가상 대시보드:

```bat
python tools/preview.py
```

브라우저에서 `http://127.0.0.1:8765`를 엽니다. 종료는 터미널의 `Ctrl+C`입니다. 이 화면은 **PC 가상값**이고 실제 MQ-2 측정값이 아닙니다. 실제 보드의 MicroPython·ADC·LED·Wi-Fi 시험을 대신하지 않습니다.

Node.js가 있는 개발 환경에서는 `node tests/test_dashboard.js`로 화면의 DOM 모의 검증도 실행할 수 있습니다. 실제 브라우저에서 화면을 렌더링하는 시험은 아닙니다. Pico 실행이나 PC 가상 대시보드 사용에 Node.js는 필요하지 않습니다.

상세 절차는 [TESTING.md](TESTING.md), 이번 검증의 범위는 [VALIDATION.md](VALIDATION.md), 개발 기록은 [DEVELOPMENT_LOG.md](DEVELOPMENT_LOG.md)를 확인하세요.

## 9. 자주 발생하는 문제

| 증상 | 확인할 내용 |
|---|---|
| `No module named machine` | PC Python으로 main.py를 실행한 상태. Thonny 인터프리터를 Pico용 MicroPython으로 선택 |
| `No module named alarm_logic` 또는 `config` | Pico 최상위 폴더에 빠진 파일이 있는지 확인 |
| `dashboard.html 파일을 ... 저장하세요` | HTML도 Pico에 업로드했는지 확인 |
| Wi-Fi 주소가 안 나옴 | SSID·비밀번호·2.4GHz·W 계열 펌웨어 확인. 센서·LED 출력은 별도로 확인 |
| 스마트폰에서 접속 안 됨 | 같은 네트워크, 기기 간 통신 차단, 새로 할당된 IP 확인 |
| 계속 예열 중 | 기본 180초 안내. 센서의 실제 안정화는 별도 확인 |
| 계속 센서 점검 | 센서 전원·공통 GND·분압·ADC 전압 확인. 안전하지 않은 입력을 코드로 숨기지 않음 |
| 노랑·빨강이 안 켜짐 | GP 번호와 물리 핀, LED 극성, 저항, config의 핀 확인 |
| 상태가 내려가는 데 오래 걸림 | 5회 복귀 확인, 히스테리시스, 진단 회복 확인이 적용됨 |
| 화면에 모의 시험이라고 표시 | `SIMULATION = False` 저장 후 Pico 재시작 |
| 휴대전화 알림이 안 뜸 | 로컬 HTTP·모바일 알림 제약. 화면 경고와 LED 사용, 원격 푸시는 별도 확장 |
